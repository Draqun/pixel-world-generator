# Design

## Context

The existing `python -m pixel_world generate` uses argparse, builds Params and invokes the terrain pipeline. It writes PNG, R16 and JSON files. Water layer CLI integration is planned separately and has not landed at this baseline. Existing direct callers use `main(argv)` and `generate(params, out)`.

## Goals / Non-Goals

**Goals:** A pleasant keyboard-driven workflow, shared validation and generation, and unchanged automated use. Users can inspect the layers actually written by the installed pipeline.

**Non-Goals:** Implementing planned generation stages, editing images, a graphical application or changing the world algorithm.

## Decisions

- Use Typer for commands and its Rich presentation for a clear menu, headings, values and errors; a numbered keyboard menu avoids an additional interactive-selection dependency and remains usable without color. Add an explicit `interactive` command and a Make target. Keep `generate` and its existing options and direct Python callers compatible, including exit codes; verify this during migration instead of assuming framework defaults match argparse.
- Present named parameters with current values, defaults, brief explanations and valid ranges; allow editing individual values and retaining the rest between runs. Require an explicit integer seed, validate with Params and show a confirmation summary. Reuse the same generation path for both modes. Returning or cancelling must not write output. Confirm before replacing generated files in an existing directory.
- Expose every interactive generation setting as a command-line option, using existing names where already defined; the same validation, defaults and generated bytes apply in both modes. Scripts remain non-interactive.
- Offer image layers known to the actual pipeline and present in the selected directory. Provide an in-terminal, size-bounded representation using terminal-compatible color or grayscale characters and the system image viewer as separate choices. The terminal representation is a scaled visual preview, not the full-resolution data. Respect terminal dimensions, provide a monochrome fallback and show the path with a recoverable error if either preview is unavailable. An embedded GUI is out of scope.
- Keep generation and serialization unchanged. Compare hashes across old-style and interactive runs and retain existing tests; a presentation-only change does not bump the generator version. Update this integration against the merged water change if it lands first.
- Add Typer through the existing uv workflow; lock the resolved dependencies. No numerical dependency changes.

## Risks / Trade-offs

- [Viewer unavailable on headless systems] → Display the path and recover without interrupting the menu.
- [Terminal capabilities and dimensions vary] → Use a bounded character preview with a monochrome fallback; report unavailable input or output without hanging.
- [Framework migration changes scripts or Python callers] → Test existing arguments, invalid input, exit codes and file hashes; retain compatibility adapters where necessary.
- [Existing output is overwritten] → Confirm before generation in interactive mode; preserve existing scripted behavior.
- [Parallel water work changes CLI or files] → Rebase and reconcile with the merged writer and output list before implementation.

## Migration Plan

Implement and validate in the ordered slices in tasks.md. Existing command lines require no migration. Roll back the interface and dependency together if necessary; generated files retain their existing format.
